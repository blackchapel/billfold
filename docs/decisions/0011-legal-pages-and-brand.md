# 0011 Legal pages, landing page and brand files

**Context.** Phases 1-6 built the product; the front door was still bare: `/privacy` and `/terms` were linked but did not exist, the front page was one paragraph, and the brand was only an SVG mark. Google also asks every OAuth consent screen for a public homepage, privacy policy and terms (project A is verified, so they must be real).

**Decisions.**
- **Public pages.** `/`, `/privacy` and `/terms` need no sign-in. They live in the `(legal)` route group with a plain shared frame (`LegalShell`), so they read well on a phone and have no app navigation. The proxy still refreshes a session if there is one; nothing else changes.
- **The policy describes what the code does**, section by section: what is stored (sign-in profile, organisation, encrypted connection secrets, bill facts with PDFs only in the user's Drive, recipients and sent emails), what each Google scope is for (`drive.file`, `gmail.readonly`, `gmail.send`, sign-in), Gemini as optional and what it receives, who else handles data (Supabase, Vercel, Google, the user's mail provider), no ads/analytics/tracking, retention and removal (soft delete, key shredding, files in Drive stay the user's), and Google's **Limited Use** statement verbatim. Any change to what the app stores or sends must change `privacy/page.tsx` and `LEGAL_UPDATED` in the same commit (also written in CLAUDE.md).
- **Terms are short and plain**: invite-only, what you are responsible for, "please check the numbers" (amounts are read automatically and can be wrong), no availability promise, no warranty, how use ends. No governing-law clause: that is the owner's decision with a lawyer. **This is not legal advice**; the owner should read both pages.
- **Contact.** `NEXT_PUBLIC_CONTACT_EMAIL` (optional) is shown as a `mailto:` link after validation (`lib/contact.ts`: one plain address, no angle brackets, quotes, spaces or line breaks). Without it the pages say to ask the person who invited you, so there is never a broken link or a made-up address.
- **Landing page.** Headline, one sentence, sign-in, then "How it works" as a numbered list of the four real steps (describe, collect, check, send) and a short "Your data stays yours" section. A list rather than a grid of cards, per the design rules. Signed-in people are still redirected into their organisation.
- **Brand files** are drawn from the same mark as `icon.svg` by `scripts/make-brand-assets.mts` (Playwright renders HTML to PNG) and committed: `public/icon-192.png`, `public/icon-512.png`, `src/app/apple-icon.png` (180, full square: iOS rounds it), `src/app/opengraph-image.png` (1200x630) with alt text. `manifest.ts` lists the two icons; `robots.ts` lets crawlers see only `/`, `/privacy` and `/terms`; the root layout sets `metadataBase`, Open Graph and Twitter card tags. A unit test checks every PNG's real size.
- **Email wordmark.** The summary email starts with "Billfold" in the serif face next to a green square, built from styled table cells, **not an image**: mail apps often block remote images, and an inline image would bloat every message. The text version ends with "Sent with Billfold".

**Consequences.** The owner must set the consent-screen links in both Google projects (see the setup guide) and may set `NEXT_PUBLIC_CONTACT_EMAIL`. The social image uses system serif fonts (Newsreader is not installed in the build sandbox); rerun the script on a machine with it if exact type matters.
